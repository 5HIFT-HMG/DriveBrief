# RSS 설명 품질 필터

기준 main e413360. 원문을 추측해서 보충하지 않고 추출 가능한 완성 문장만 사용한다. 중요도 점수·그룹화·가중치·사람 승인 정책은 변경하지 않는다.

## 처리 순서

1. 원본 RSS 메타데이터는 articles에 보존한다. 수집 종료 시 article_content_quality에 버전, 재생 가능 여부, 제외/제거 사유, 정제 설명을 기록한다. 실패한 수집 주기에도 저장된 기사를 재점검한다.
2. 클로징·오프닝·방송/뉴스 예고·끝인사 같은 독립 제목은 로컬 후보와 자동 브리핑에서 제외한다. '뉴욕증시 클로징 벨 행사'처럼 실제 기사의 단어 일치는 제외하지 않는다.
3. 사진/방송 메타데이터 기호 ▲△■□▶▷가 들어간 설명 구간은 기호만 지우고 읽지 않고 해당 구간을 제외한다. 사진 설명과 본문이 붙어서 경계가 불명확하면 복원을 시도하지 않는다. 다음 독립 완성 문장은 유지할 수 있다.
4. 사진·영상·제공 등의 괄호 메타데이터, 시작 기자명(인턴/수습 포함), 기자 소개 문장, 이메일·저작권·제보 꼬리표를 정리한다. '사진 제공' 크레딧에 붙은 앞 문장은 사진 설명으로 보수적으로 제외한다.
5. 문장 경계 뒤 공백이 없는 한국어도 분리한다. 소수 3.5와 정상 인용·수치·부정 표현·의미 있는 괄호는 유지한다.
6. …, ⋯, ..., […]가 있는 설명 구간, 문장 종결 형태가 없는 꼬리, 350자를 초과하는 문장은 제외한다. 앞부분의 완성 문장을 남길 수 있지만 잘린 문장을 생성하거나 이어 붙여 복원하지 않는다.
7. 정제한 설명이 공백 제외 50자 미만이거나 완성 문장이 없으면 RSS 자동 브리핑에서 제외한다. 제목만 읽어 분량을 채우지 않는다. MIN_DESCRIPTION_CHARACTERS가 초기 기준이다.
8. 자동 브리핑을 만들기 전에 필터를 통과시킨다. 저장된 게시본을 재사용할 때도 정제 상태를 검증하므로 이전 오염 게시본을 그대로 재사용하지 않는다. 최근 원본은 있으나 모두 품질 미달이면 세 옵션 모두 빈 목록으로 원자적으로 게시한다. 요청 실패/최근 원본 없음은 기존 오류 정책을 유지한다.

RSS 추출은 AI 요약이나 사람 승인으로 바꾸지 않는다. 짧게/중간/길게의 1/3/5문장 정책과 동일 기사 순서는 유지한다. 실제 요약 승인 DB와 과거 청취 스냅샷은 변경하지 않는다.

## 점검과 테스트

```sh
SUPABASE_URL='' SUPABASE_SECRET_KEY='' python3 -m unittest discover -s news_crawler/tests -q
cd backend
SUPABASE_URL='' SUPABASE_SECRET_KEY='' .venv/bin/python -m unittest discover -s tests -q
```

자동 테스트에서는 실제 환경설정을 비워 네트워크와 DB 쓰기를 격리한다.

읽기 전용 기존 자료 점검:

```sh
python3 news_crawler/content_quality.py --db news_crawler/news.sqlite3
```

## 적용 및 제한

이 브랜치의 자동수집_시작.command 또는 run-local.command를 사용하면 해당 수집 주기에서 품질 점검과 정제 게시가 계속 적용된다. 이전 버전 프로세스는 새 코드를 자동으로 읽지 않으므로 종료 후 이 버전으로 재실행해야 한다. 외부 서버에 별도 수집기를 운영 중이면 이 PR 적용 후 재시작해야 한다.

이번 실행 도구에서 백그라운드 수집의 RSS/DB 연결은 Connection refused로 실패하여 작업이 만든 백그라운드 프로세스는 정리했다. 원본 수집 실패 시 기존 데이터는 유지된다. 직접 수행한 공유 DB 게시/재조회는 성공했으며 새 RSS 자동수집 성공과 구분한다.

50자 기준은 정상 단신도 제외할 수 있다. 무표식 사진 설명·복잡한 괄호·인용·방송 형식은 규칙만으로 완벽하게 구분할 수 없다. 경계가 불분명한 내용을 임의 재작성하는 대신 보수적으로 제외한다. 기존 사용자의 과거 OnePaper에는 당시 원본 스냅샷이 남으며 새 브리핑부터 정제된 자료를 사용한다.

## 제목의 편집 코너명

제목 앞뒤 대괄호의 알려진 편집 코너명(오그랲·에디터픽·AFTER 8 SPECIAL·지식의 발견·이슈대담·뉴시스Pic 등)을 재생용 제목에서 제거한다. 연속된 표시는 반복 제거한다. 알 수 없는 대회명·기관명, 제목 중간의 괄호, 인용 내용은 일괄 삭제하지 않는다. 원본 news_articles 제목은 보존한다. 공동 기자명이 2~5명 적힌 시작 바이라인도 정리하며 본문 속 기자의 발언은 보존한다.

수집기 40개·백엔드 167개 테스트 통과. 실제 최근 후보 200건에서 제목 4건이 정제 대상이었다. 세 옵션 25건을 다시 게시하고 DB에서 재조회하여 알려진 코너명 잔여와 공동 바이라인이 0건임을 확인했다. 새 브리핑부터 적용하며 과거 OnePaper 스냅샷은 바꾸지 않는다.
