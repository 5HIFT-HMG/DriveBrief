# 모닝 뉴스 — 개인용 무료 시제품

현재 수집 대상은 7개 언론사·37개 RSS입니다. 추가 출처와 적용 방법은 [RSS_SOURCES.md](RSS_SOURCES.md)를 확인하세요. 자동수집_시작.command는 5분 간격으로 실행합니다.

화면 개수는 전체 DB 기사 수, 선택 날짜의 URL 기준 고유 후보 수, 실제 선정 수를 구분합니다. 선택 날짜에서 분야별 최대 5개를 고르며, 관심 키워드별 제목 일치 +3점·RSS 설명 일치 +1점을 합산하고 동점이면 최신순으로 정렬합니다. 같은 분야의 URL 또는 정규화한 제목이 같으면 제외합니다. 출처별 균등 배분이나 의미 기반 동일 사건 통합은 하지 않습니다. 브라우저에서 관심사를 바꾸면 화면 선정이 달라지며 JSON 파일은 config.json의 관심사로 생성됩니다.

제목과 RSS 설명은 HTML 엔티티를 먼저 해제하고 태그·스크립트·스타일을 제거한 일반 텍스트로 저장·표시합니다. 반복 인코딩된 태그와 불필요한 공백도 정리합니다. 기존 DB의 제목·설명도 수집 시 정리하며 기사 날짜·출처·원문 링크는 유지합니다. 이는 RSS 설명 형식 정리이며 기사 전문 또는 LLM 요약 생성이 아닙니다.

## 가장 쉽게 실행하기 (Mac)

1. 이 폴더 안의 **뉴스_가져오기.command**를 더블클릭합니다.
2. 수집이 끝나면 브라우저에 **내_뉴스.html**이 열립니다.
3. 기본은 어제 기사입니다. 첫날 어제 기사가 부족하면 **오늘 기사 보기**를 눌러 확인하세요.
4. 관심사 칸에 `AI, 반도체, 야구`처럼 입력하고 **관심사 적용**을 누릅니다.
5. **선택 기사 읽기**로 제목과 RSS 설명을 들을 수 있습니다. 기기에 한국어 음성이 설치되어 있어야 하며, 기기 내 음성만 사용합니다. 지원 여부는 브라우저와 운영체제에 따라 다릅니다.

Python 3.10 이상이 필요합니다. 개발한 현재 컴퓨터에는 Python 3.13이 설치되어 있습니다. 추가 패키지, API 키, 유료 API는 사용하지 않습니다. 브라우저와 수집기는 외부 분석 서비스로 데이터를 보내지 않습니다. 수집기는 RSS 제공처에 직접 접속합니다.

실행 파일이 바로 열리지 않으면 터미널에서 `python3 `을 입력한 다음 **news.py 파일을 터미널로 드래그**하고, 뒤에 ` --collect --open`을 붙여 Enter를 누르세요. 명령은 `python3 /파일의/전체경로/news.py --collect --open` 형태입니다.

## 매일 자동으로 모으기

**자동수집_시작.command**를 더블클릭하고 열린 창을 유지하세요.

- 시작할 때 바로 수집하고 이후 1시간마다 수집합니다.
- 매 수집 후 한국 시간 기준 어제의 브리핑 화면과 JSON을 새로 만듭니다. 별도의 아침 6시 작업을 설치하는 방식이 아니라, 하루가 바뀐 뒤 다음 수집에서 전날 날짜로 자동 전환합니다.
- 다음 날 아침 **내_뉴스.html**을 열면 됩니다. 이미 열려 있다면 새로고침하세요.
- 중지: 터미널 창에서 Control+C. 다시 시작해도 저장된 기사는 유지됩니다.
- 컴퓨터 종료·잠자기·인터넷 끊김 동안 수집을 보장하지 않습니다. 잠자기에서 돌아오면 가능한 다음 시점에 재개하며, 재부팅 후에는 실행 파일을 다시 열어야 합니다.
- 이 대화에서 자동 수집을 백그라운드 서비스로 설치하거나 시작하지는 않았습니다.

## 무엇을 수집하나요?

| 분야 | RSS 출처 |
|---|---|
| 경제·사회·정치·스포츠 | SBS의 각 분야 RSS |
| IT | 전자신문 IT와 SW·AI RSS |

- [SBS 공식 RSS 안내](https://news.sbs.co.kr/news/rss.do)
- [전자신문 공식 RSS 안내](https://rss.etnews.com/)

제목, 원문 링크, RSS 설명, 제공된 기사 시각, 수집 시각을 저장합니다. RSS 본문 확장 필드·이미지·추적 픽셀은 불러오지 않습니다. 날짜가 없거나 시간대가 불명확한 기사는 제외합니다. 날짜는 RSS가 제공한 시각을 한국 시간으로 변환한 기준이며 실제 사건 발생일과 다를 수 있습니다.

RSS에는 최근 기사 일부만 남을 수 있습니다. 따라서 과거 기사 전체와 전날 기사 전체를 보장하지 않습니다. IT는 해당 RSS 제공처의 분류를 따르므로 모든 IT 뉴스의 포괄적 목록은 아닙니다.

## 선정 방식과 설정

조회수·공감 TOP 5가 아닙니다. 분야별 **관심사 추천 최대 5개**입니다.

- 제목에서 키워드 일치: 단어당 3점
- RSS 설명에서 키워드 일치: 단어당 1점
- 동점: 기사 시각 최신순
- 키워드를 비우면 최신순
- 같은 링크 또는 공백·문장부호를 제거한 동일 제목은 분야 안에서 중복 제거
- 같은 사건의 다른 제목은 아직 묶지 않습니다. 같은 기사는 여러 분야에 나타날 수 있습니다.
- 분야별 기사가 5개 미만이면 있는 만큼만 표시하며 다른 날짜 기사로 채우지 않습니다.

화면에서 바꾼 관심사는 브라우저에 저장됩니다. 자동 생성 JSON과 새 브라우저의 기본값을 바꾸려면 **config.json**에서 `keywords`를 수정하세요. `limit`는 분야별 개수(1~20), `feeds`는 RSS 출처 설정입니다. JSON 문법을 유지하세요.

## 파일 설명

- **내_뉴스.html**: 실제 수집 결과 화면. 더블클릭해서 열기
- **내_뉴스.json**: 기본 설정으로 선정한 어제의 분야별 기사. 향후 앱 연결용
- **news.sqlite3**: 수집한 기사 보관 파일. 자동으로 지우지 않습니다.
- **news.py**: 수집·저장·선정 프로그램
- **report.html**: 화면 생성용 틀. 직접 열 파일은 내_뉴스.html입니다.
- **config.json**: 기본 관심사·분야별 개수·RSS 주소

화면은 최근 30일의 저장 데이터를 담습니다. 데이터베이스에는 이전 기록도 유지됩니다. 데이터베이스와 뉴스 화면 파일은 개인 컴퓨터에 보관하고 외부에 게시하지 마세요.

## 명령으로 사용하기 (선택)

이 폴더에서 다음을 실행합니다.

```sh
python3 news.py --collect --open
python3 news.py --watch --open
python3 news.py --date 2026-11-06 --open
python3 -m unittest discover -s tests -v
```

아무 옵션 없이 실행하면 저장된 기사로 어제 화면만 다시 만듭니다. `--date`는 브리핑 선정 날짜이며 과거 뉴스를 새로 검색하는 옵션이 아닙니다. 화면에 담는 범위는 최근 30일이고 JSON은 지정 날짜의 저장 기사로 생성합니다. 자동 수집할 때는 `--date`를 고정하지 마세요.

## 수집 실패가 나오면

화면 아래 **수집 상태와 이용 안내**에서 출처별 마지막 성공과 오류를 확인하세요. 한 출처가 실패해도 다른 출처의 결과와 기존 기사는 남습니다. 모든 출처가 실패하면 프로그램은 오류 상태로 끝나지만 기존 데이터로 화면을 생성합니다. 인터넷 연결과 RSS 주소를 먼저 확인하세요. 추후 제공처가 주소를 바꾸면 config.json을 수정해야 합니다.

## 사용 범위

개인용 뉴스 리더 시제품입니다. SBS는 RSS를 개인의 비상업적 사용에 한해 제공한다고 명시합니다. RSS가 공개되어 있다는 사실만으로 상업 서비스·재배포·AI 요약·음성 제공의 모든 사용권이 생기지는 않습니다. 외부 사용자에게 제공하기 전에는 각 제공처와 해당 사용 범위를 확인해야 합니다.

이 버전에는 실제 조회수·공감순 정렬, AI 본문 요약, 사용자 계정, 자동차 연결, 서버 운영은 포함하지 않았습니다.

## 기사 본문 수집

기존 RSS 명령은 그대로 유지합니다. `--full-text`를 추가하면 RSS 수집 후 본문 수집을 수행하며 `--watch`와 함께 사용할 수 있습니다.

```sh
python3 news.py --collect --full-text
python3 news.py --watch --interval 300 --full-text
```

`config.json`의 `body_sources`에서 확인된 출처만 활성화합니다. 아래는 설정 형식 예시이며 실제 출처 설정이 아닙니다.

```json
{"body_sources": {"news.example.org": {"collection_allowed": true, "element_id": "article-body"}}}
```

`element_id`를 생략하면 NewsArticle/Article JSON-LD의 articleBody를 추출합니다. RSS 설명이나 페이지 전체 텍스트를 본문으로 대체하지 않습니다. 출처 설정이 없으면 본문 요청을 보내지 않습니다. 본문은 기존 articles 테이블을 변경하지 않고 article_bodies에 저장합니다. 주기마다 최신 기사부터 최대 20건을 처리하고, 성공 건은 재요청하지 않으며 실패 건은 재시도합니다. 이 구현은 기사 수정 감지·본문 자동 갱신을 포함하지 않습니다. 수집 허용 설정은 외부 AI 처리·요약 재사용 허가를 의미하지 않습니다.

실제 페이지 수집·FastAPI 본문 연결·외부 AI 요약은 아직 검증하지 않았습니다. 기존 `/v1/news` 응답과 가상 기사 승인 파이프라인은 유지합니다.
